### Frame-level beats

- A 1.0 s establishing wide, then the push lands on the line before the first keystroke.

Read from 10-frame strips around 5 cuts and 2 moves; 1 f = 16.7 ms at 60 fps. Dark editor: at strip size the code is texture, and only the highlighted line and the autocomplete panel read.

- **The push ends in 3 columns** (1.33 s in all, about 0.4 s of travel): from the three-pane window to the code column alone, with the active line's grey highlight bar at about 50% of the height. Columns 4–10 are a settle under 2%.
- **The active line is a full-width bar.** A lighter band marks the line being typed in every held frame; it is the only horizontal mark in a frame of left-aligned code, at the same height (about 55%) for the whole 15 s hold.
- **Autocomplete opens under the line, 6 frames after the keystroke** (2.33 s): a panel about 45% of the frame wide and 8 rows tall, lighter than the editor; it is the largest change in the hold, and it opens between two frames.
- **New lines push the file down, not the frame.** At 7.32 and 10.07 s the block below the active line shifts down one row between two frames as a line is added; the frame doesn't follow, so the active line stays at the same height.
- **The second autocomplete repeats the first** (10.07 s): same position, same size, 5 frames after the keystroke.
- **The pull crosses to the preview.** From 16.81 s the frame leaves the code in 2 columns (smeared), and by column 5 the whole window is in view with the chat at the left and the code at the right; columns 6–10 hold. At 20.93 s the right pane's content changes to a wider code view between two frames.

**Eye at the cuts.** There are no edits. Through the hold the eye stays on one line at about 30–50% × 55%. Code → whole window: the code column moves from the centre to the right half, about 25%, inside the pull. All 5 measured cuts are editor changes.

## 3. Diagnose

- ×2 on the line held for 15.8 s while autocomplete works. → One zoom for one task.
- Push and pull are critically damped springs. → Screen Studio's camera: front-loaded and soft.

## 5. Critique

- **I like:** The frame stays fixed while the code changes, so the change is the only motion.
- **I wish:** 15.8 s at one framing is long for a showreel.
- **I wonder:** Could a long hold be cut down to its first and last seconds in a reel?
