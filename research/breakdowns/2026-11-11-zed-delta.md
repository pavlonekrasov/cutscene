## 2. Classify

Narrative product film: named people, clock times, a deadline, subtitled like a short story. Conventions: a caption track, locked windows, jump cuts, side-by-side sessions, an end card with commands.

## 3. Diagnose

- Subtitles name people, times and a deadline. → Story structure (setup, conflict, resolution): the use case is a scene with stakes, not a feature list.
- The subtitle sits in the same place under the window every shot. → A consistent caption track: the viewer always knows where to read, so cuts never cost orientation.
- Two sessions side by side while the second agent works. → Parallel action without a cut (Cursor, Family, Figma, Notion, Zed).
- Jump cuts between states of one locked window, 98% still. → Progress shown by cuts, not camera: the frame holds and time jumps.

## 4. Prescribe

- _new_: A caption track: one subtitle line per shot, under the frame, same position every shot. (renderer caption (not built))
- _new_: Tell the use case as a story with a person, a time and a deadline. (reel script (skill))
- _confirms_: Side-by-side windows for parallel action. (split frame (Part 2))
- _confirms_: cutscene 0.3.0's curve matches a hand-made 0.79 s pan (rms 0.38%). (camera curve (exists))

## 5. Critique

- **I like:** 'Hard stop at six' gives a developer tool a deadline, which makes a sync feature feel like relief.
- **I wish:** The windows are small on the page, so the subtitles carry the story and the UI is mostly texture.
- **I wonder:** Could each reel scene carry one subtitle line from its scene file, set in a fixed caption track under the frame?

## Not for us

- A terminal app and a chat app outside the browser.
